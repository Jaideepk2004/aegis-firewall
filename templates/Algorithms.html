[ Algorithm 01 ]
Tabular · qlearning.py

Q-Learning

The foundation of the AI Adaptive Firewall. Q-Learning builds a lookup table mapping every (state, action) pair to an expected future reward. It's the simplest RL algorithm — and the clearest way to understand how the agent learns to classify packets.

Bellman Update Equation Q(s, a) ← Q(s, a) + α × [ r + γ · maxa' Q(s', a') − Q(s, a) ]
α = learning rate (0.10) | γ = discount factor (0.90) | ε = epsilon-greedy (1.0 → 0.05)
[ 01 ]

What it is

Q-Learning is a tabular, model-free RL algorithm. It stores Q-values in a Python dictionary keyed by a discretised state tuple. Each entry holds three floats — one Q-value per action (ALLOW, BLOCK, RATE-LIMIT). No neural network, no function approximation.

[ 02 ]

How it works in the Firewall

(10 bins per feature) creating a discrete state key. At every step the agent picks the highest Q-value action, observes the reward from FirewallEnv, then updates that Q-value using the Bellman equation. Epsilon decays from 1.0 → 0.05 over 50 episodes.

[ 03 ]

Its limitation

With 8 features × 10 bins = up to 10⁸ possible state keys, the Q-table only learns states it actually visits and cannot generalise to nearby but unseen states. This is exactly what motivated the move to DQN — replace the table with a neural network that interpolates between states.

[ Algorithm 02 ]
Neural Network · dqn.py

Deep Q-Network

DQN replaces the Q-table with a neural network. Instead of storing millions of discrete states, a single network takes any 8-feature packet vector as input and outputs one Q-value per action — continuous states, no discretisation needed.

DQN Loss (Mean Squared Error) L = MSE( Q_online(s, a), r + γ · maxa' Q_target(s', a') )
Q_online → updated every step | Q_target → frozen copy, synced every 500 steps
[ 01 ]

What it is

DQN (DeepMind, 2013–2015) introduces two key innovations over Q-Learning: experience replay (store transitions, sample random mini-batches to break temporal correlation) and a frozen target network (stable TD targets stop the loss from chasing a moving goal).

[ 02 ]

How it works in the Firewall

The QNetwork (8 → 128 → 64 → 3) takes a scaled packet feature vector and outputs Q-values for ALLOW, BLOCK, and RATE-LIMIT. Transitions are pushed to a 10,000-slot ReplayBuffer. Every step, a 64-sample mini-batch is drawn, the MSE loss is computed against the frozen target net, and gradients are clipped at norm 1.0 before the Adam step.

[ 03 ]

Why it bridges to PPO

DQN still outputs Q-values — it derives the policy implicitly by taking argmax. PPO removes Q-values entirely and learns action probabilities directly. DQN is the conceptual bridge: it proves neural networks can approximate RL, while PPO improves training stability with clipped policy updates.

[ Algorithm 03 — Deployed ]
Policy Gradient · train_ppo.py

Proximal Policy
Optimization

PPO is a fundamentally different approach — instead of estimating Q-values, it directly learns a policy: a probability distribution over actions. Clipped updates keep each training step inside a safe "trust region", making it the most stable and best-performing algorithm in the AI Adaptive Firewall.

PPO Clipped Objective LCLIP = E[ min( ratio · A, clip(ratio, 1−ε, 1+ε) · A ) ]
ratio = πnew(a|s) / πold(a|s) | A = advantage = Q(s,a) − V(s)
clip_range = 0.20 | The clip prevents any single update from changing the policy too drastically
[ 01 ]

What it is

PPO (OpenAI, 2017) is an on-policy actor-critic algorithm. It maintains two networks: an actor π(a|s) that outputs action probabilities, and a critic V(s) that estimates expected return. The clipped surrogate objective prevents the policy from making catastrophically large jumps in any single update step.

[ 02 ]

How it works in the Firewall

The AI Adaptive Firewall trains PPO in 10 phases of 20,000 timesteps each (200,000 total) using Stable-Baselines3's MlpPolicy. After each phase the policy is evaluated deterministically on 5,000 steps and the reward is logged. The final model is saved as adaptive_firewall_ppo.zip and loaded by the Flask dashboard at startup.

[ 03 ]

Why it's the deployed model

PPO directly outputs action probabilities — no argmax over Q-values needed. On-policy learning means the agent always trains on its own recent experience, well-suited to the Firewall's sequential packet stream. Its stability and higher accuracy over Q-Learning and DQN made it the production choice for the Flask dashboard.
